# LLM Vocab Trainer

PWA для усвоения профессиональной англоязычной лексики (ИТ и информационная безопасность) с интервальным повторением и генерацией заданий языковой моделью.

## Запуск

Нужен Python 3.12+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # затем заполните значения (TEACHER_PASSWORD)
alembic upgrade head        # применить миграции
python -m app.seed          # загрузить стартовые карточки
python -m app.verify_seed   # пометить карточки сида проверенными (см. ниже)
uvicorn app.main:app --reload
```

- Проверка: http://localhost:8000/health возвращает `{"status": "ok"}`
- Документация API: http://localhost:8000/docs

## Интерфейс студента

После запуска `uvicorn app.main:app --reload` откройте http://localhost:8000/ : вход по имени, затем повторение. Сессия пуста, пока карточки не проверены (`python -m app.verify_seed`).

Установка как приложения (PWA): в Chrome или Edge на ПК - значок установки в адресной строке; на Android - меню Chrome, «Установить приложение»; на iPhone - Safari, «Поделиться», «На экран Домой». Для установки с телефона нужен HTTPS (исключение только `localhost`), см. этап деплоя.

Фронтенд лежит в `static/` (чистые HTML, CSS и JS-модули без сборки). При изменении списка файлов оболочки обновите `SHELL` и версию `CACHE` в `static/sw.js`.

## Проверка карточек

Загрузка сида (`app.seed`) создает карточки с `verified=false`, и в сессию студента они не попадают. Если `data/cards.json` изменился после первой загрузки, обновите карточки в базе командой `python -m app.seed --update` (у измененных карточек сбрасывается `verified`). Перед командой `python -m app.verify_seed` содержимое `data/cards.json` нужно просмотреть глазами (транскрипции, определения, примеры, типичные ошибки): команда помечает проверенными все карточки сида сразу.

## Вход (упрощение прототипа)

- Студент входит по имени без пароля: `POST /auth/login` с `{"name": "..."}`. Тот же ввод имени дает тот же аккаунт, поэтому чужим именем можно воспользоваться.
- Преподаватель входит с `"role": "teacher"` и общим паролем из `TEACHER_PASSWORD` в `.env`. Если пароль не задан, вход преподавателя отключен.
- Ответ содержит случайный токен, который хранится в БД и передается в заголовке `Authorization: Bearer <token>`. Срока действия у токенов и выхода из системы пока нет.
- Создание, правка, удаление и проверка карточек доступны только преподавателю.

## Генерация заданий через LLM

Провайдер выбирается в `.env`: `LLM_PROVIDER=fake` (по умолчанию, без ключа и сети) или `LLM_PROVIDER=gigachat`.

Для GigaChat нужны:
- `GIGACHAT_CREDENTIALS` - «Ключ авторизации» из личного кабинета;
- `GIGACHAT_SCOPE=GIGACHAT_API_PERS` (тариф для физических лиц);
- модель по умолчанию `GigaChat-2`, задается `GIGACHAT_MODEL`.

Адреса API берутся из официального SDK `gigachat` (версия 0.2.3: `https://api.giga.chat/v1`, авторизация `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`). Подключение проверялось только до уровня создания клиента, реальный запрос с ключом еще не выполнялся.

Проверка TLS включена всегда. Для нее используется корневой сертификат НУЦ Минцифры `certs/russian_trusted_root_ca_pem.crt`. Он публичный, скачан с https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt (Russian Trusted Root CA, действует до 27.02.2032, SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`). Отключать проверку сертификата нельзя.

В модель уходят только поля карточки, тип задания и уровень студента. Имена и ответы студентов в запрос не попадают.

### Валидация и банк заданий

Сгенерированное задание показывается студенту только после проверки (`app/services/validation.py`):
- правила без LLM: ровно 4 уникальных варианта, правильный ответ среди них; для `gap_fill` ответ равен термину, а сам термин в тексте скрыт; для `definition_match` правильный вариант равен определению из карточки;
- второй запрос к LLM: какие варианты подходят и использован ли термин в значении из карточки. Подходить должен только правильный вариант. Проверяет та же модель, что и генерирует, это ограничение метода.

При отказе задание генерируется заново (первая попытка плюс до 2 повторов, `GenerationConfig.max_retries`). Прошедшие проверку задания сохраняются в таблицу `task_bank` вместе с источником (`gigachat:GigaChat-2`, `fake`), записи разных источников не смешиваются. Если для карточки и типа в банке уже есть 3 задания (`bank_min_size`), запрос к LLM не делается. Цепочка при сбоях: генерация, затем банк, затем алгоритмическое задание из полей карточки.

В ответе `GET /session/next` у сгенерированного задания есть `task_id`, его нужно передавать в `POST /session/answer`. Первая генерация задания занимает несколько секунд (до 3 попыток по 2 запроса).

### Открытые задания и классификация ошибок

Задания `explain_meaning` и `compose_sentence` появляются на поздних этапах усвоения. Ответ классифицируется (`app/services/classification.py`): пустой ответ и попытки повлиять на проверку определяются правилами, неверное написание термина - сравнением, остальное - LLM (получает только термин, карточку, задание и текст ответа). Для `compose_sentence` клиент передает в ответе поле `context` (ситуация из задания). Если классификатор недоступен, `POST /session/answer` возвращает 503, ничего не записывая: ответ можно отправить повторно.

Проверка генерации вручную:

```bash
python -m app.generate vulnerability gap_fill
```

Типы заданий, которые генерирует LLM: `gap_fill`, `definition_match`. Остальные типы (в том числе выбор словосочетания) строятся алгоритмом из полей карточки, см. `DECISIONS.md`.

## Структура

- `app/main.py` - точка входа FastAPI
- `app/config.py` - настройки из `.env`
- `app/db.py` - подключение к БД и сессии
- `app/api/` - маршруты, `app/models/` - таблицы, `app/schemas/` - Pydantic-схемы
- `app/seed.py`, `data/cards.json` - загрузка стартовых карточек
- `app/llm/` - адаптеры LLM (`fake`, `gigachat`), шаблон запроса
- `app/services/generation.py` - сборка запроса и разбор ответа модели
- `certs/` - корневой сертификат для GigaChat
- `alembic/` - миграции
- `tests/` - тесты pytest
- `static/` - фронтенд PWA для студента (HTML, CSS, JS-модули, service worker, манифест, иконки)

## Секреты

Ключи хранятся только в `.env` (он в `.gitignore`). Шаблон - `.env.example`.
