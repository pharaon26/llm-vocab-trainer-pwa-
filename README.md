# LLM Vocab Trainer

PWA для усвоения профессиональной англоязычной лексики (ИТ и информационная безопасность) с интервальным повторением и генерацией заданий языковой моделью.

## Запуск через Docker

Нужен Docker (Docker Desktop на macOS и Windows).

```bash
cp .env.example .env        # заполните POSTGRES_PASSWORD, TEACHER_PASSWORD и при необходимости ключи GigaChat
docker compose up --build   # PostgreSQL + приложение; миграции применяются при старте
docker compose exec app python -m app.seed          # загрузить стартовые карточки (один раз)
docker compose exec app python -m app.verify_seed   # пометить карточки сида проверенными (см. ниже)
```

- Приложение: http://localhost:8000/ (порт задается `APP_PORT`), проверка: http://localhost:8000/health
- Документация API: http://localhost:8000/docs
- Данные PostgreSQL лежат в именованном томе `pgdata` и переживают `docker compose down`; полностью стереть базу: `docker compose down -v`.
- Контейнер приложения работает не от root. Адрес базы внутри compose подставляется автоматически (хост `postgres`), `DATABASE_URL` из `.env` нужен только для запуска на хосте.

### Переменные `.env`

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | имя базы, пользователь и пароль PostgreSQL (обязательны) |
| `DATABASE_URL` | адрес базы для запуска на хосте: `postgresql+psycopg://USER:PASSWORD@localhost:5432/DB` (обязателен) |
| `TEACHER_PASSWORD` | общий пароль преподавателя; пусто - вход преподавателя отключен |
| `LLM_PROVIDER`, `GIGACHAT_CREDENTIALS`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL` | провайдер модели, см. раздел о генерации |
| `DICTIONARY_PROVIDER` | `dictionaryapi` или `none` |
| `SESSION_TTL_DAYS` | срок жизни сессии входа, по умолчанию 30 |
| `COOKIE_SECURE` | флаг Secure у cookie сессии; по умолчанию `true` (cookie уходит только по HTTPS), для локального http поставьте `false` |
| `ALLOWED_ORIGINS` | адреса приложения через запятую, с которых принимаются изменяющие запросы (проверка `Origin`); по умолчанию `http://localhost:8000,http://127.0.0.1:8000`, в продакшене укажите свой https-адрес |
| `TRUSTED_PROXIES` | адреса и сети обратных прокси через запятую; только от них принимается `X-Forwarded-For` |
| `DICTIONARY_AUDIO_DOMAINS` | домены, с которых разрешены ссылки на произношение |
| `APP_PORT`, `POSTGRES_PORT` | порты на хосте (8000 и 5432); порт БД открыт только на `127.0.0.1` |

## Запуск на хосте (для разработки)

Нужен Python 3.12+ и запущенный PostgreSQL (проще всего `docker compose up -d postgres`).

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env        # затем заполните значения
alembic upgrade head        # применить миграции
python -m app.seed          # загрузить стартовые карточки
python -m app.verify_seed   # пометить карточки сида проверенными (см. ниже)
uvicorn app.main:app --reload
```

## Интерфейс студента

После запуска `uvicorn app.main:app --reload` откройте http://localhost:8000/ : регистрация или вход по имени и паролю, затем повторение. Сессия пуста, пока карточки не проверены (`python -m app.verify_seed`).

Разделы (нижнее меню; настройки открываются ссылкой в шапке):

| Раздел | Что показывает | API |
|---|---|---|
| Повторение | Задания на сегодня: новые термины (по умолчанию 5 в день) и повторения по расписанию. После ошибки термин повторяется еще раз в этой сессии | `GET /session/next`, `POST /session/answer` |
| Прогресс | Все проверенные термины со статусом (новый, изучаю, выучен), дата следующего повторения, ошибки по типам | `GET /me/progress` |
| Словарь | Карточки уже открытых терминов (транскрипция, определение, перевод, словосочетания, примеры), поиск. Здесь же «Добавить термин», «Добавить из текста», черновики и «Мои слова» | `GET /me/dictionary`, `/me/drafts`, `/me/cards`, `/me/extract` |
| История | Все ответы: задание, мой ответ, правильный ответ, тип ошибки, дата; фильтр по термину | `GET /me/history` |
| Статистика | Точность по дням, мои ошибки по типам (столбики на SVG), серия дней подряд | `GET /me/stats` |
| Настройки | Число новых терминов в день (от 1 до 20) и наборы для изучения | `GET`, `PUT /me/settings`, `GET`, `PUT /me/decks` |

Статус «выучен»: интервал повторения от 21 дня и нет ошибки, ожидающей повтора (значение в `LearningConfig`).

**Области и наборы.** У карточки одна область (IT, Information security, Medicine, Law, Economics, Engineering, преподаватель может добавить другие). Карточки собраны в наборы; стартовые 24 карточки образуют набор «IT & Security basics» (он выбран по умолчанию). Студент выбирает наборы в настройках: новые термины берутся только из выбранных наборов, а повторение уже открытых терминов продолжается даже после снятия набора.

**Свои слова.** В «Словаре» студент нажимает «Добавить термин» (слово или словосочетание и область) или «Добавить из текста» (вставляет фрагмент, модель предлагает до 15 терминов, студент отмечает нужные). Приложение собирает черновик: транскрипция, часть речи, определение, примеры и аудио берутся из Free Dictionary API (dictionaryapi.dev), недостающее (перевод, словосочетания, типичные ошибки, контрастный термин, профессиональное определение, если общее не подходит) предлагает LLM. Для каждого поля хранится источник (словарь, модель, студент), поля модели помечены «модель: проверьте». Черновик попадает в повторения только после просмотра и кнопки «Подтвердить»: тогда он становится личной карточкой студента (видна только ему и преподавателю, в аналитику группы не входит). Если слово уже есть, предлагается существующая карточка. Если внешний словарь недоступен (например, из России), запрос прерывается по таймауту в 3 секунды, и черновик собирает только модель. На создание черновиков и поиск терминов действует дневной лимит обращений к модели на студента (`DraftConfig.daily_llm_limit`, 30). Текст для поиска терминов уходит в GigaChat, в интерфейсе есть предупреждение, длина ограничена (4000 знаков). Если словарь нужно отключить, задайте `DICTIONARY_PROVIDER=none` в `.env`.

**Свободная тренировка.** Когда задания на сегодня выполнены, на экране «На сегодня всё» появляется кнопка «Свободная тренировка»: задания по уже открытым терминам (чаще по тем, где были ошибки). Ответы пишутся в историю с пометкой «тренировка», но не передаются планировщику и не меняют интервалы (`GET /practice/next`, `POST /practice/answer`). В прогресс, точность и аналитику преподавателя они не входят, число тренировочных ответов показывается отдельно. Подробности решений - в `DECISIONS.md`.

Установка как приложения (PWA): в Chrome или Edge на ПК - значок установки в адресной строке; на Android - меню Chrome, «Установить приложение»; на iPhone - Safari, «Поделиться», «На экран Домой». Для установки с телефона нужен HTTPS (исключение только `localhost`), см. этап деплоя.

Фронтенд лежит в `static/` (чистые HTML, CSS и JS-модули без сборки). При изменении списка файлов оболочки обновите `SHELL` и версию `CACHE` в `static/sw.js`.

## Кабинет преподавателя

Страница http://localhost:8000/teacher.html : вход с именем и паролем из `TEACHER_PASSWORD` (укажите его в `.env`, иначе вход отключен). Разделы: карточки (создание, правка, проверка, удаление), наборы (состав, область, «по умолчанию», добавление областей), личные карточки студентов (просмотр, правка, «Поднять в общий набор» после проверки), банк заданий (можно убрать сомнительное задание) и аналитика группы (ошибки по типам и самые трудные термины, столбики на SVG). Ответы свободной тренировки в аналитику не входят, их число показывается отдельно.

## Проверка карточек

Загрузка сида (`app.seed`) создает карточки с `verified=false`, и в сессию студента они не попадают. Если `data/cards.json` изменился после первой загрузки, обновите карточки в базе командой `python -m app.seed --update` (у измененных карточек сбрасывается `verified`). Перед командой `python -m app.verify_seed` содержимое `data/cards.json` нужно просмотреть глазами (транскрипции, определения, примеры, типичные ошибки): команда помечает проверенными все карточки сида сразу.

## Вход и учетные записи

- **Студент** регистрируется по имени и паролю (не короче 8 символов): `POST /auth/register` с `{"name": "...", "password": "...", "password_confirm": "..."}` (пароль вводится дважды, сервер отклоняет несовпадение), затем входит через `POST /auth/login`. Пароль хранится только в виде хеша argon2. В интерфейсе у экрана входа есть ссылка «Создать аккаунт», которая открывает отдельную страницу «Регистрация».
- **Преподаватель** отдельной регистрации не имеет: на странице `/teacher.html` достаточно ввести любое имя и пароль из `TEACHER_PASSWORD` в `.env` (укажите его до запуска), при первом входе учетная запись создается сама. Если пароль не задан, вход преподавателя отключен.
- **Студенты, созданные до появления паролей,** войти не могут. Пароль им задает администратор: `docker compose exec app python -m app.set_password ИМЯ` (запросит пароль без показа на экране).
- **Сессия** - серверная, в cookie `session` (`HttpOnly`, `Secure`, `SameSite=Lax`, `Path=/`). Фронтенд не хранит и не отправляет токен: браузер сам прикладывает cookie. В базе лежит только хеш идентификатора (SHA-256) и срок жизни (`SESSION_TTL_DAYS`, 30 дней). При каждом входе прежняя сессия этого браузера заменяется новой. Выход: `POST /auth/logout` (кнопка «Выйти» в интерфейсах студента и преподавателя) удаляет сессию в базе и стирает cookie.
- **CSRF:** изменяющие запросы (`POST`, `PUT`, `PATCH`, `DELETE`) принимаются, только если заголовок `Origin` (или `Referer`, когда `Origin` нет) совпадает с адресом из `ALLOWED_ORIGINS`; иначе `403`. Для вызовов API без браузера (например, `curl`) нужно передавать заголовок `Origin` с разрешенным адресом.
- **CSP:** все ответы (кроме `/docs`, `/redoc`) содержат `Content-Security-Policy`: скрипты и стили только с собственного домена, без inline и `eval`; аудио - только с доменов словаря.
- **Ограничение попыток:** после 5 неудачных входов за 15 минут для одного имени или одного IP вход блокируется ответом `429` с заголовком `Retry-After`. Попытки хранятся в таблице `login_attempts`. Те же правила действуют для пароля преподавателя. IP берется из адреса соединения; `X-Forwarded-For` учитывается, только если соединение пришло с адреса из `TRUSTED_PROXIES`.
- Создание, правка, удаление и проверка карточек доступны только преподавателю.

## Генерация заданий через LLM

Провайдер выбирается в `.env`: `LLM_PROVIDER=fake` (по умолчанию, без ключа и сети) или `LLM_PROVIDER=gigachat`.

Для GigaChat нужны:
- `GIGACHAT_CREDENTIALS` - «Ключ авторизации» из личного кабинета;
- `GIGACHAT_SCOPE=GIGACHAT_API_PERS` (тариф для физических лиц);
- модель по умолчанию `GigaChat-2`, задается `GIGACHAT_MODEL`.

Адреса API берутся из официального SDK `gigachat` (версия 0.2.3: `https://api.giga.chat/v1`, авторизация `https://ngw.devices.sberbank.ru:9443/api/v2/oauth`). Подключение проверялось только до уровня создания клиента, реальный запрос с ключом еще не выполнялся.

Проверка TLS включена всегда. Для нее используется корневой сертификат НУЦ Минцифры `certs/russian_trusted_root_ca_pem.crt`. Он публичный, скачан с https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt (Russian Trusted Root CA, действует до 27.02.2032, SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`). Отключать проверку сертификата нельзя.

В модель уходят только поля карточки, тип задания и уровень студента. Имена и ответы студентов в запрос не попадают.

### Валидация и банк заданий

Сгенерированное задание показывается студенту только после проверки (`app/services/validation.py`):
- правила без LLM: ровно 4 уникальных варианта, правильный ответ среди них; для `gap_fill` ответ равен термину, а сам термин в тексте скрыт; для `definition_match` правильный вариант равен определению из карточки;
- второй запрос к LLM: какие варианты подходят и использован ли термин в значении из карточки. Подходить должен только правильный вариант. Проверяет та же модель, что и генерирует, это ограничение метода.

При отказе задание генерируется заново (первая попытка плюс до 2 повторов, `GenerationConfig.max_retries`). Прошедшие проверку задания сохраняются в таблицу `task_bank` вместе с источником (`gigachat:GigaChat-2`, `fake`), записи разных источников не смешиваются. Если для карточки и типа в банке уже есть 3 задания (`bank_min_size`), запрос к LLM не делается. Цепочка при сбоях: генерация, затем банк, затем алгоритмическое задание из полей карточки.

В ответе `GET /session/next` у сгенерированного задания есть `task_id`, его нужно передавать в `POST /session/answer`. Первая генерация задания занимает несколько секунд (до 3 попыток по 2 запроса).

### Открытые задания и классификация ошибок

Задания `explain_meaning` и `compose_sentence` появляются на поздних этапах усвоения. Ответ классифицируется (`app/services/classification.py`): пустой ответ и попытки повлиять на проверку определяются правилами, неверное написание термина - сравнением, остальное - LLM (получает только термин, карточку, задание и текст ответа). Для `compose_sentence` клиент передает в ответе поле `context` (ситуация из задания). Если классификатор недоступен, `POST /session/answer` возвращает 503, ничего не записывая: ответ можно отправить повторно.

Проверка генерации вручную:

```bash
python -m app.generate vulnerability gap_fill
```

Типы заданий, которые генерирует LLM: `gap_fill`, `definition_match`. Остальные типы (в том числе выбор словосочетания) строятся алгоритмом из полей карточки, см. `DECISIONS.md`.

## Тесты

Тесты идут на PostgreSQL, в отдельной базе `<POSTGRES_DB>_test` (создается автоматически, схема строится миграциями; имя обязано заканчиваться на `_test`). Каждый тест выполняется в транзакции с откатом.

```bash
docker compose up -d postgres   # если база еще не запущена
pytest
```

Другая тестовая база задается переменной `TEST_DATABASE_URL`.

## Структура

- `app/main.py` - точка входа FastAPI
- `app/config.py` - настройки из `.env`
- `app/db.py` - асинхронное подключение к БД (SQLAlchemy async, psycopg) и сессии
- `app/security.py` - хеши паролей и токенов, определение IP клиента
- `Dockerfile`, `docker-compose.yml`, `docker-entrypoint.sh` - запуск в контейнерах
- `app/api/` - маршруты, `app/models/` - таблицы, `app/schemas/` - Pydantic-схемы
- `app/seed.py`, `data/cards.json` - загрузка стартовых карточек
- `app/llm/` - адаптеры LLM (`fake`, `gigachat`), шаблон запроса
- `app/services/` - логика: планировщик, сессия, задания, валидация, банк, классификация ответов, прогресс и статистика студента, аналитика
- `app/api/me.py`, `app/api/personal.py`, `app/api/practice.py`, `app/api/teacher.py` - разделы студента, свои слова, тренировка, кабинет преподавателя
- `app/dictionary/` - клиент внешнего словаря (dictionaryapi.dev, фейковый для тестов)
- `certs/` - корневой сертификат для GigaChat
- `alembic/` - миграции
- `tests/` - тесты pytest
- `static/` - фронтенд PWA (HTML, CSS, JS-модули без сборки, service worker, манифест, иконки), `static/teacher.html` - кабинет преподавателя
- `DECISIONS.md` - журнал проектных решений
