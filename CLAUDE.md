# CLAUDE.md

## О проекте

Веб-приложение (PWA) для усвоения профессиональной англоязычной лексики студентами технических направлений. Приложение объединяет интервальное повторение и генерацию учебных заданий языковой моделью (LLM).

Проект делается к научной статье «Проектирование веб-приложения для усвоения профессиональной лексики с использованием языковых моделей и интервального повторения». **Логика приложения должна совпадать с тем, что описано в статье.** Если реализация расходится со статьей, сообщи об этом, а не меняй логику молча.

Предметная область прототипа: англоязычная терминология ИТ и информационной безопасности (vulnerability, authentication, encryption, patch, deployment и т. д.).

Авторы - студенты, которые изучают бэкенд-разработку. Код пишешь ты, но авторы должны понимать каждую часть проекта и уметь объяснить ее преподавателю и рецензенту.

## Правила работы

1. **Сначала логика, потом код.** Перед каждым этапом объясни простыми словами, что будет сделано и как это работает. Код пиши только после подтверждения.
2. **Работай по этапам** из раздела «План». Не начинай следующий этап, пока текущий не проверен и не принят.
3. **После каждого этапа** кратко объясни, какие файлы созданы, что делает каждый и как проверить результат вручную.
4. **Не принимай решения из раздела «Открытые решения» сам.** Спроси.
5. **Не усложняй.** Это прототип. Никаких микросервисов, очередей, Kubernetes и т. п., если об этом не попросили.
6. **Секреты только в `.env`.** Ключи API, пароли и т. п. никогда не попадают в репозиторий. `.env` в `.gitignore`, в репозитории лежит `.env.example`.
7. **Пиши тесты** (pytest) для логики планировщика, валидации и классификации ошибок.
8. В документации и комментариях на русском используй обычный дефис «-», а не длинное тире.

- **Бэкенд:** Python 3.12+ (у авторов установлен 3.14), FastAPI, Pydantic v2, SQLAlchemy 2.0, Alembic.

## Предметная модель

### Эталонная карточка (Card)

Поля: термин, транскрипция, часть речи, определение на английском, перевод на русский, 2-4 словосочетания (collocations), 2-3 проверенных примера, типичные ошибки, контрастный термин (например, vulnerability - threat), предметная область, флаг «проверено преподавателем».

**Карточку меняет только человек.** LLM не может изменять карточки, она только использует их при генерации заданий.

### Типы ошибок

| Тип | Описание | k (сохранение интервала) | δ (снижение E) |
|---|---|---|---|
| form | написание, грамматическая форма | 0,5 | 0,10 |
| meaning | неверное значение, смешение с похожим термином | 0 (сброс) | 0,20 |
| usage | неверная часть речи, неподходящий контекст | 0,5 | 0,15 |
| collocation | нарушение типичных словосочетаний | 0,6 | 0,10 |

### Правило расчета интервалов (модификация SM-2)

- После первого успешного ответа: I₁ = 1 сутки, после второго: I₂ = 3 суток.
- Верный ответ: Iₙ₊₁ = Iₙ · E. Коэффициент легкости E от 1,3 до 2,5, начальное значение 2,5.
- Ошибка типа t: Iₙ₊₁ = max(1; Iₙ · kₜ), E' = max(1,3; E − δₜ).
- После любой ошибки термин повторяется еще раз в той же сессии и на следующий день, тип задания выбирается по типу ошибки.
- Все коэффициенты вынести в конфиг: это начальные параметры, они будут уточняться.

Проверочный пример из статьи (должен быть в тестах): I = 8, E = 2,5. Верный ответ: 20 суток. Ошибка form: 4 суток, E = 2,4. Ошибка meaning: 1 сутки, E = 2,3.

### Типы заданий

| Аспект | Узнавание | Употребление |
|---|---|---|
| Форма | выбрать правильное написание | записать термин по определению |
| Значение | сопоставить с определением, отличить от контрастного термина | объяснить своими словами в 1-2 предложениях |
| Употребление | вставить термин в пропуск | составить предложение в заданной ситуации |
| Словосочетания | выбрать сочетающийся глагол или прилагательное | дополнить словосочетание и использовать в предложении |

Каждое задание сначала требует вспомнить ответ без подсказки, и только потом показывает эталон.

## Конвейер генерации заданий

1. Планировщик отбирает термины, срок повторения которых наступил.
2. Для каждого термина выбирается тип задания (по этапу усвоения и последней ошибке).
3. Запрос к LLM собирается по фиксированному шаблону: роль, термин и поля карточки, предметная область, уровень студента, тип задания, формат ответа (строгий JSON).
4. **Валидация:**
   - ответ соответствует JSON-схеме, длина в допустимых пределах;
   - правильный ответ совпадает с целевым термином, термин используется в значении из карточки;
   - задание однозначно (например, в задании на пропуск подходит только один вариант).
5. Если проверка не пройдена: повторная генерация, не более 2 попыток. Затем берется проверенное задание из банка заданий.
6. Прошедшие проверку задания сохраняются в банк для повторного использования.

**Работа с LLM вынесена за отдельный интерфейс (класс-адаптер)**, чтобы провайдера можно было заменить, не трогая остальной код. Для тестов и разработки без ключа нужен фейковый провайдер.

**В LLM не передаются персональные данные.** Только термин, поля карточки и текст ответа студента.

## Оценка ответов

- Простые ошибки (написание) определяются сравнением с эталоном без LLM.
- Сложные (значение, употребление, словосочетания) классифицирует LLM, получая только термин, карточку и ответ.
- Ответ и тип ошибки сохраняются в историю.

## Интерфейсы

- **Студент:** сессия повторения на сегодня, выполнение заданий, показ эталона после ответа.
- **Преподаватель:** создание и проверка карточек, просмотр банка заданий, аналитика группы (термины с наибольшей долей ошибок, распределение ошибок по типам).

## План (этапы)

1. **Каркас проекта:** структура, FastAPI, база, миграции, `.env.example`, README с инструкцией запуска.
2. **Карточки:** модель, CRUD API, загрузка 20-30 стартовых карточек из файла.
3. **Планировщик:** расчет интервалов по правилу выше + тесты (включая пример из статьи).
4. **Сессия повторения без LLM:** простые задания из полей карточки, проверка ответа, запись истории.
5. **Генерация заданий через LLM:** адаптер, шаблоны промптов, фейковый провайдер.
6. **Валидация и банк заданий** + тесты.
7. **Классификация ошибок** + тесты.
8. **Фронтенд PWA для студента**, установка на телефон.
9. **Интерфейс преподавателя и аналитика.**
10. **Деплой** с HTTPS.
